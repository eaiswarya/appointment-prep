# Writing Flyway Migrations

## Overview

The schema lives only in `backend/src/main/resources/db/migration`, and migrations are **append-only**. Hibernate runs with `ddl-auto=validate`, so entities must match the migrated schema exactly. JPA never creates tables.

## Rules

1. **The line is "merged to `main`".** A `V*` file that is on `main` is frozen. Editing or renaming it breaks the Flyway checksum in every environment, so fix mistakes with a new migration.
   - A migration on an **unmerged** branch, even one already pushed or under review, may be edited.
   - Anyone who already ran the old version locally must reset their dev DB with `docker compose down -v`. Say so in the PR notes.
2. **Name** files `V<next-integer>__<snake_case_description>.sql`, e.g. `V7__add_booking_reminder_index.sql`.
   - Check the highest number on `main` **and** in open PRs: `gh pr list --json headRefName`, then look at their migration files.
   - If two PRs use the same number, renumber the one that merges second.
3. **Repeatable** migrations (`R__*.sql`) are only for views and dev seed data. Dev seed data lives in `db/dev/`.
4. **Expand → migrate → contract** for anything destructive:
   1. add the new column or table;
   2. backfill and switch the code over;
   3. drop the old one in a **later** PR.

   Never drop or rename a column in the same PR that stops using it.

## Conventions

| Thing | Convention |
|---|---|
| Timestamps | `timestamptz`, never `timestamp` |
| IDs | `uuid` (UUIDv7, generated by the app); no DB defaults |
| Enums | `varchar` + `CHECK (col IN (...))`, mirrored by a Java `enum` with `@Enumerated(STRING)` |
| Constraints | Always named: `<table>_<purpose>`, e.g. `bookings_no_provider_overlap` |
| FKs | Index every FK column that is used in lookups |
| Time ranges | `tstzrange(start, end, '[)')`; GiST index or exclusion constraint (needs `btree_gist`) |

## Gotchas

- **Generated columns must be `IMMUTABLE`.** `timestamptz + interval` is not, which is why `bookings.blocked_until` is written by the app (TECHNICAL_DESIGN §5.3).
- **Exclusion constraints referenced by name in Java** (`GlobalExceptionHandler` maps `bookings_no_provider_overlap` → `SLOT_TAKEN`). Renaming one breaks the error mapping, so update both places and the tests.
- **Adding a `NOT NULL` column to a table with data:** add it nullable, backfill, then `SET NOT NULL`. Or give it a constant default.
- **Large index on a hot table:** use `CREATE INDEX CONCURRENTLY` in its own migration, with `-- flyway:executeInTransaction=false` on the first line.

## Verification

- Add or extend a Testcontainers test that runs all migrations on a clean DB. `./mvnw verify` does this, because the app context starts with `validate`.
- For constraints, write a test that **violates** the constraint and asserts the error, not just a happy-path insert.
- Changed a table the API exposes? Use the `adding-api-endpoint` skill for the DTO and client changes.
